> **整合基线说明（2026-11-24）：** 新基线为 `8664f26`，包含 Aster 主线/F1（`2ff46e1`）、G1（`9655a48`）及 H1（`e97f82f`）全部分支最终优化。原准备工作与 P1.1、P1.2.1 代码已按原顺序保留，提交 ID 因重建历史而变化。整合版后续 P1.2.2 至 P1.2.4 已由用户确认实机验收通过；新增提交仍须逐阶段回归。H2 封面任务未实现，未扩大当前开发范围。


**一个核心，多种体验。**

PrismOS 是基于 [Aster 固件](https://github.com/a505283042/aster-firmware) 的轻量嵌入式系统项目。保留原有系统核心与应用兼容性，将公共界面逻辑和独立主题分离，支持自由选择桌面主题、系统字体和提示音。

首发验证设备为 FakePod Nano Pro（ESP32-S31），保留 ESP32-S3 和 ESP32-P4 原有平台支持。

## 三层系统架构

| 层级 | 职责 | 复用方式 |
| --- | --- | --- |
| 系统核心（System Core） | 设备、音频、网络、存储、应用生命周期 | 完全共用 |
| 公共界面框架（UI Shell） | 显示调度衔接、输入、桌面切换、快捷面板、系统设置 | 所有主题共用 |
| 独立界面主题（UI Theme） | 桌面布局、动画、配色、图标和交互风格 | 每套主题独立 |

```text
       FLUX / Probe（验证） / 后续主题
                  │
           公共 UI Shell
      主题 / 字体 / 提示音选择
                  │
         Aster 系统核心（保留）
                  │
          现有 HAL 与板级驱动
                  │
       ESP32-S3 / S31 / P4
```

主题不仅仅是换色，而是允许不同桌面布局、动画和交互方式。所有主题共用原有音频、网络、应用生命周期、显示宿主及系统服务。字体和提示音可独立选择，不强制跟随主题。

初期主题布局随固件编译，运行时切换无需重启；可选字体、提示音和主题数据资源通过 TF 卡安装。不引入通用脚本或插件框架。

## 开发原则

- 保留 Aster 系统核心、应用二进制接口（ABI）、应用运行时、现有驱动和平台适配。
- 公共界面框架只协调现有 UI 调度，不新建 UI 线程，不重写 LVGL 或显示流水线。
- 每套主题独立实现表现层，系统级动作共用；只激活一套主题，不为每个主题分配常驻全屏缓冲。
- 复用现有字体加载器、提示音服务、快捷面板、配置存储及应用安装机制。
- 不因主题、字体或提示音切换停止后台音乐。
- 每阶段独立提交、测试及回退，不提前重构 HAL、BSP、商城、SDK 或资源服务器。
- 保持原有首次开机下载协议与旧应用资源路径，不格式化用户 TF 卡。

### P1.3.1 主题诊断（ESP-IDF）

`aster ui theme stats` 或 `aster ui mem`：由 UI 所有者输出本次启动累计切换统计、活动屏幕对象数、全局 LVGL 定时器数、艺术缓存及内部 RAM/PSRAM 空闲量、历史最低值、最大连续块和分配块数。诊断在 benchmark 期间延后，不修改主题或配置。P1.3 实机已记录 24 次成功切换及 18.3/18.2 FPS；堆内存、重启恢复与后台播放仍待补充验收。

### P1.3.2 生命周期隔离及压力诊断

`aster ui theme trace on|off` 开关阶段采样；`aster ui theme stress 100` 从空闲 FLUX 发起 100 次切换（50 次往返），每 10 次输出一次统计；`aster ui theme stress stop` 停止。测试期间不要操作桌面或启动 APP。主题切换及目录刷新不触发 APP 返回音；S31 原生音频独占 DAC 时跳过旧 UI 音效，保留原硬件互斥保护。未确认内存下降根因，待新版本实机采样。
