## 1. 项目目标和范围

以 Aster 固件为基础，将现有桌面中混合的公共系统界面逻辑与主题表现逻辑分开，建立轻量的公共 UI Shell。保留 Aster 系统核心、现有应用及硬件支持，完成三项个性化功能：
- 多套独立桌面主题：不同布局、动画、配色、图标及桌面交互，不只是换色。
- 多套系统字体：复用 cpfont 与现有字形缓存，可独立选择。
- 多套系统提示音：复用原有音效通路，可独立选择及关闭。

首发验证板为 FakePod Nano Pro（ESP32-S31，ESP-IDF 6.1，460×460 CO5300）；同时维持原有 ESP32-S3 Zephyr 和 ESP32-P4 ESP-IDF 构建兼容。按现有板卡文档选择 SDK、工具链及依赖，不强制统一后端，不新增芯片适配任务。保留 Aster ABI 4.5.0、WAMR AOT、应用安装及旧资源路径、音频服务、现有 HAL、LCD 16 行乒乓流水线和回退开关。

本期不做：通用插件/包管理框架、声明式或脚本主题引擎、系统服务注册框架、产品配置框架、BSP 重构、S3 IDF 移植、独立商城或资源发布服务器、OTA、独立 SDK/驱动/主题仓库、全局重命名 aster_*。资源服务器及品牌扩展另行评审，不作为当前验收前置。个性化资源初期从 TF 卡手动安装，不改变现行首次初始化 11 项协议，不增加网络强制依赖。

## 2. 三层架构（已确定）

| 层级 | 职责 | 复用方式 |
|---|---|---|
| 系统核心（System Core） | 设备、音频、网络、存储、应用生命周期、硬件抽象、图形底层 | 完全共用，沿用 Aster |
| 公共界面框架（UI Shell） | 显示调度衔接、输入分发、桌面生命周期、主题切换、快捷面板、系统设置 | 所有主题共用 |
| 独立界面主题（UI Theme） | 桌面布局、动画、配色、图标、应用列表呈现及主题特有交互 | 每套主题独立实现 |

```text
 FLUX 主题       Classic 主题       后续主题
     └──────────────┬───────────────┘
                    │ 主题接口
              公共 UI Shell
     显示 / 输入 / 生命周期 / 快捷面板
       主题切换 / 字体选择 / 提示音选择
                    │ 现有系统接口
            Aster 系统核心（保留）
   设备 / 音频 / 网络 / 存储 / 应用生命周期
                    │ 现有 HAL / BSP
       S3 Zephyr / S31 IDF / P4 IDF
```

依赖方向：主题调用 Shell 提供的公共状态和系统动作；Shell 调用现有核心服务；核心不引用具体主题。Shell 是现有 UI 调度的公共协调层，不另建 UI 线程，不重写 LVGL、显示驱动、LCD 流水线或 APP worker。字体与提示音是公共 UI 资源，与主题独立选择，不属于某个主题的专属系统服务。

## 3. 职责及状态归属

| 内容 | 归属 | 处理方式 |
|---|---|---|
| LVGL 显示实例、DMA/PPA、帧缓冲 | 原核心/现有 UI 宿主 | 保留，Shell 负责衔接而非重新创建 |
| APP 前台、启动/退出/安装、后台音乐 | 原应用与音频服务 | 保留原所有权与接口 |
| 桌面显示/隐藏、空闲等待、UI 事件调度 | Shell | 沿用原 worker 及调用顺序 |
| 系统按键、全局手势、息屏/唤醒 | Shell 与原电源服务 | 复用原实现，只有公共逻辑移出主题 |
| 快捷面板、Wi-Fi、蓝牙、退出确认、配网/救援 | 公共 UI | 保留现有组件和行为 |
| APP 目录、音量、亮度、电池、网络状态 | 核心状态/公共 UI 状态 | 使用原服务或快照，不另建重复真值 |
| 主题 ID、字体 ID、提示音 ID | Shell 个性化设置 | 独立持久化，使用现有 KV |
| 选中项、滚动位置、布局、动画 | 各主题 | 私有状态，不影响其他主题 |
| 系统字体、音效资源 | 公共字体/音效选择模块 | 复用原加载和播放通路 |

输入处理顺序：现有系统紧急操作及电源逻辑 → 公共覆盖层/快捷面板 → 当前 APP 或桌面主题。具体优先级以原行为回归为准。系统 Home/退出/恢复手势不可被主题劫持。主题可消费其桌面范围内的滑动、点击和导航；APP 前台时不向隐藏主题转发桌面输入。音量、亮度、息屏时长和音乐播放状态不得保存在多个主题各自的副本中。

## 5. 主题接口和生命周期

拟议 C 接口（示例，具体类型、命名和返回值在 P1.1 按现有源码确定）：
```c
typedef struct {
    const char *id;
    const char *name;
    int  (*init)(void);
    int  (*show)(lv_obj_t *parent);
    void (*hide)(void);
    void (*tick)(void);
    void (*on_input)(const ui_event_t *event);
    void (*on_apps_changed)(void);
} ui_theme_t;
```

- id 为稳定字符串（如 flux、classic），不依赖注册顺序；name 用于界面显示。静态注册表只登记编译期已有主题。
- init 初始化主题轻量状态，不启动独立任务。show 创建指定父容器下的主题对象，失败返回错误；Shell 持有容器。hide 停止并清除主题自己的动画、定时器、订阅、对象和资源引用，应允许清理部分初始化的状态。
- tick 仅更新活动主题；沿用原空闲等待节奏，必要时扩展 idle_wait_ms、palette 和可选 diagnostics 回调，不为未使用的扩展设计大量接口。
- on_input 仅接收 Shell 路由后的桌面输入，on_apps_changed 使用现有注册表快照刷新列表，避免保留已失效指针。
- 主题可通过公共动作启动应用、打开面板和请求反馈音，不直接停止音乐、重设电源、修改 DMA 或清理整个 LVGL 活动屏幕。
- 保留 FLUX 性能统计及 bench 的行为。主题专用统计可经可选诊断接口转发，不把 FLUX 内部状态作为第二主题的强依赖。

初期主题布局由 C 代码随固件编译，运行时切换无需重启；TF 卡仅允许静态数据资源（图片、配色等按需支持），不能直接安装任意新 C 布局或执行外部原生代码。未来增加主题需新增实现并注册后重新构建固件，不改系统核心。首版不引入脚本解释器。

## 6. 主题切换事务与资源约束

所有 LVGL 对象操作和切换事务由现有 UI 所有者执行。快捷面板或其他任务只发布切换请求，不直接销毁桌面。建议流程：
1. 接收目标主题 ID，检查注册及适用性；相同主题直接返回，不重复重建。
2. 检查前台 APP、配网、安装、USB MSC、诊断或其他独占状态。不能安全切换时拒绝或延期至桌面空闲点；后台音乐播放不等同于前台 APP，原则上可切换。
3. 等待触摸释放，关闭覆盖层，重置旧手势，停止主题动画，安全完成在途显示提交。不得在 DMA 仍引用待释放缓冲时释放资源。
4. 保存旧主题私有状态，hide 旧主题；释放对象、计时器、图标/艺术资源引用。保留核心服务、公共配置和现有显示宿主。
5. 建立新主题容器，init/show；检查创建结果和有效首帧的提交状态。
6. 成功后提交活动主题 ID 和现有 KV；若写入失败，报告并保留一致状态（明确恢复旧主题或仅本次生效，不伪报已持久化）。
7. 新主题创建失败时清理半成品，优先恢复旧主题，仍失败恢复内置 FLUX/安全界面；启动时无效 ID 同样回退，禁止循环重启。

只允许一套活动主题。非活动主题不保留活动 LVGL 对象、周期定时器或全屏缓冲。460×460 RGB565 单帧为 423200 字节，双帧为 846400 字节，不含对齐/临时缓冲；不因为多主题复制现有显示缓冲。沿用 S31 16 行乒乓流水线及关闭回退机制。资源缓存受内存限制，优先释放旧主题缓存。切换不重新初始化 I2S、DAC、蓝牙、播放队列或应用运行时。

a. 桌面显示/隐藏、应用切换时的界面清理及恢复。

### P1.4：第二套独立主题
选择 Classic 或 Minimal 之一作为首版第二主题，不要求同时实现 Grid。应拥有明确不同的应用列表/桌面布局及导航表现，不只是 FLUX 改色。

- 用主题注册方式接入，验证新增主题不要求改核心、APP worker、驱动。
通过条件：两套桌面可选择，重启恢复；连续往返切换至少 100 次，预热后内存无持续下降趋势，无残留计时器/对象/输入事件；后台播放无可归因于切换的新增断音，原 APP、覆盖层、息屏和回退正常。

### P2：多套字体
- 沿用 cpfont 与现有字形缓存，不开发新字体渲染引擎。默认路径 /SD/aster/fonts/ui_<px>.cpfont 不变，旧 AOT APP 继续使用原契约，固定启动/救援字体不变。
- 扩展字体家族目录（拟议），至少默认字体和一套合法自定义字体：
```text
/SD/aster/fonts/
  ui_18.cpfont
  ...
  families/rounded/
    font.json
    ui_18.cpfont
    ...
```
- 最小 font.json 字段：稳定 ID、显示名、格式版本、可用字号及文件信息；许可随字体提供。实际文件格式以现有转换器和加载器为准；不建通用包协议。
- 复用现有字号和字形加载逻辑；缓存键区分 family/size/glyph，限制总体缓存；缺字号/字符回退默认字体，默认文件也不可用时使用内置救援字体可覆盖的字符。
- 第一版全局系统字体选择即可；主题可提供建议默认值，但用户选择优先。字体切换只针对桌面和可安全替换字体的公共 UI；HiFi/旧 AOT APP 的字体或歌词接口不自动改变，不要求本期适配。
- 切换在 UI 安全点进行，先验证文件与必要字形、停止旧布局引用，再重建使用新字体的对象，旧引用释放后才能关闭缓存。失败保留原字体或回退默认；成功保存稳定 ID。
- 检查文字宽度、行高、基线及截断，必要时只调整相关布局。限制 TF 冷读及预热开销，避免抢占音频供给。
通过条件：两字体在两主题内独立组合、重启恢复；切换主题不强制重置字体，缺字/缺字号/损坏/无卡安全回退，长标题、中英文、数字显示正常，无持续内存增长或音频回归。

### P3：多套提示音
先检查现有 FLUX 操作音、公共 UI 音效入口、音频所有权及实际支持格式。只封装现有播放能力，不增加 I2S 输出任务或改动实时音乐链路。
拟议资源：
```text
/SD/aster/sounds/
  classic/
    sound.json
    click.wav
    confirm.wav
    back.wav
    error.wav
  soft/
    sound.json
    click.wav
    confirm.wav
    back.wav
    error.wav
```
- WAV/PCM 为候选格式；采样率、位宽、声道、长度、解码方式按原链路能力确定，必要时离线转换。默认音效保留；自定义文件不是开机强制依赖。
- 最小 sound.json 记录 ID、显示名、格式版本、已有事件与文件对应关系。限制时长、大小、缓存和触发频率；不要求所有事件必须存在。
- 通过现有 UI 动作触发确认/返回/点击/错误等实际支持的音效，避免在滚动每帧、触摸移动重复播放。
- 当前播放链路不支持安全混音、音频忙、蓝牙路由不支持或设备无音频能力时，允许跳过；绝不暂停音乐、切换 DAC、重设蓝牙或改变全局音量来强行播放。
- 选择默认、自定义或关闭，独立保存。缺失、格式不支持或损坏回退默认/静音。开关机音和复杂混音不作为本期要求。
通过条件：至少两套提示音和关闭选项可用、重启保存；两主题一致调用公共反馈音，用户选择不随主题切换重置；连续操作无堆积、爆音或音乐中断，异常资源安全处理。

### P4：个性化设置整合与最终回归
复用已有设置或快捷面板提供统一入口：
```text
个性化
  桌面主题    FLUX / Classic
  系统字体    默认 / 自定义
  系统提示音  默认 / 自定义 / 关闭
  恢复默认    仅恢复以上三项
```
三项配置独立持久化；如提供跟随主题选项，只在用户明确选择时使用建议值。恢复默认不清除 APP、存档、音乐、Wi-Fi、音量、亮度或其他系统设置。
- 手动复制 TF 资源，目录扫描限制数量、路径长度及文件大小；拒绝非法路径、重复 ID、损坏文件，不阻塞 UI 长时间等待 I/O。
- 保留原资源下载及商城，不增加联网要求，不格式化用户 SD。
- S31 完整回归，S3/P4 构建及可用真机验证；对照 P0 的性能和音频数据，记录所有未验证项。
完成条件见第 9 章。

## 8. 公共配置、兼容与性能约束

| 项目 | 要求 |
|---|---|
| 主题 ID | 稳定字符串，缺失默认 FLUX，不依赖数组位置 |
| 字体 ID | 独立选择，默认沿用旧字体路径 |
| 提示音 ID | 独立选择，保留默认及关闭 |
| 主题私有状态 | 每主题独立保存，避免频繁写 TF |
| 旧配置迁移 | 版本化、幂等，不删除原有用户数据 |
| UI 所有权 | 唯一现有线程，不增加并行 LVGL 实例 |
| 音频所有权 | 现有核心服务；主题无权改实时播放链路 |
| 文件系统 | 使用现有存储接口，检测卡状态并处理错误 |
| 内存 | 仅活动主题保留对象和动画，缓存有界，沿用显示缓冲 |
| 硬件兼容 | 使用已有 HAL、实际屏幕尺寸和能力查询 |
| 首次初始化 | 原 11 项资源协议、URL、TLS 校验和商城不变 |

性能要求以 P0 实测为基线，而非预设未经测量的 FPS。相同固件配置、板卡和播放负载比较空闲/滚动/切换阶段；分别记录冷字体缓存和热缓存。切换峰值、可用内存、最长帧间隔及音频欠载单独记录。不得通过降低默认音频稳定性或关闭现有显示优化来掩盖 UI 回归。必要时限制主题动画质量、分块加载或回退静态资源，但不要重写底层。

## 9. 验收矩阵

| 场景 | 预期结果 |
|---|---|
| 冷启动/重复启动 | 选择项正确恢复；无效 ID 回退默认 |
| FLUX → 第二主题 → FLUX | 布局独立，公共面板、应用启动和系统动作一致 |
| 连续 100 次主题切换 | 无持续内存泄漏、残留动画或触摸事件 |
| 切换时触摸未释放 | 等待或安全取消，不误触 |
| APP 前台/配网/安装/USB MSC | 拒绝或延期切换，无生命周期冲突 |
| 音乐后台播放时切换三项 | 不停止音乐、不重新初始化音频，无新增可归因断音 |
| 字体缺字/缺字号/损坏文件 | 回退默认或内置救援字体 |
| 提示音缺失/静音/输出忙 | 默认或跳过，无爆音和音乐中断 |
| 低内存、创建失败 | 清理半成品，恢复旧主题或 FLUX |
| TF 卡缺失/拔出/写保护/断电 | 安全报错、恢复既有配置，不清卡 |
| 旧 APP 运行与返回桌面 | 原 ABI、路径、安装注册表和生命周期保持兼容 |
| 不同屏幕尺寸及平台 | 原板型至少可构建；适配布局或默认回退 |
| 恢复默认 | 只恢复主题、字体、提示音 |
| 性能基准 | 对照 P0，无未解释的明显回归；音频实时性优先 |

主机测试重点：静态主题注册和非法 ID、状态机、重复请求、失败清理、KV 迁移与回退、字体/音效清单边界；真实 LVGL 生命周期和 DMA 完成、字体视觉、音频、功耗必须真机验证，不能只用 mock 结论替代。每阶段记录测试项目、构建身份、结果、未测试项与回退提交。无实机环境时不宣称实机通过。
