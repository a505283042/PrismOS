# 电源与实体按键适配

系统内部接口位于 `common/port/aster_power.h`，不改变 APP 的 WASM/AOT ABI。
公共实现不依赖 ESP-IDF、Zephyr、PMIC 型号或 GPIO 编号。

## 硬件操作表

`aster_power_ops_t` 提供能力查询、电池读取、屏幕开关、CPU 休眠、重启、关机、实体按键读取和语义映射。
`aster_power_device_base` 使用既有设备接口提供屏幕与按键的默认实现。

新板调用 `aster_power_derive(&board_ops, &aster_power_device_base, &overrides)`：
非空回调覆盖父表，其余方法继承；如需删除继承的方法，派生后显式置空。
操作表、名称和 context 必须具有静态生命周期，所有继承方法接收同一个 context，不能隐含使用另一张父表的 context。
`aster_power_bind()` 在启动阶段注册，`aster_power_seal()` 后不能替换，避免运行中的表和驱动被换掉。
OS 生命周期表同样支持 `aster_power_lifecycle_derive()` 局部覆盖。

能力声明区分熄屏、浅休眠、深休眠、重启和关机，三个可唤醒模式分别声明唤醒源。
例如触摸可以唤醒仅关闭背光的设备，并不表示该触摸 GPIO 能从深休眠中唤醒 CPU。
不支持的方法为 NULL，查询/执行返回负 errno。能力查询会过滤没有回调的方法。
电池数据通过有效标志区分无电池、未知电量、有效百分比和有效电压，不从电压假算百分比。
硬件原始按键 code 不进入 Launcher 的板型判断；板级 map_key 回调映射为系统语义。

## 系统生命周期

`aster_power_lifecycle_t.prepare/finish` 是 OS/应用/文件系统收尾适配。
CPU 休眠、重启、关机必须同时具备硬件方法和这两个钩子，否则能力查询过滤该功能。
prepare 成功前必须获得排他状态，停止新安装/下载，结束或暂停 VM 与音频，等待工作线程完全退出，完成存储同步。
失败时 prepare 自己恢复未完成的准备；成功后，硬件调用返回时公共层总会调用 finish，负责唤醒或失败恢复。
熄屏只改变显示，不停止后台蓝牙或本地音乐，不执行破坏性收尾。

所有运行期接口由系统 UI/VM 的同一个 owner 调用；总线竞争由驱动内部处理。
绑定表不可变不代表驱动自动线程安全。其他线程需要通过命令队列交给 owner，不能直接调用此状态机。

## 公共熄屏策略

`aster_power_idle_t` 提供无分配、无常驻任务的超时状态机。
timeout=0 表示从不自动熄屏，inhibited 用于按住触摸、安装等临界阶段。
用户活动刷新计时；熄屏后的首次触摸会唤醒并吞掉该次手势，直到全部触点抬起，避免唤醒时误点击。
Launcher 和应用覆盖层共用策略，设置独立保存，不改变旧设置的存储格式。

## 当前接入范围

- 三块板共用可滚动设置、自动熄屏、立即熄屏与触摸唤醒。
- S31 状态栏用 LVGL 几何图形绘制电池外框、百分比填充和充电闪电，不依赖字库图标；低电量使用警示色。
- S31 额外读取 AXP2101 电池状态/充电状态/百分比，并对 GPIO61 按键做 30ms 消抖；短按熄屏/唤醒，长按请求返回桌面。
- AXP2101 只读 STATUS1/2 和 SOC，不改充电电流、供电电压或校准数据。
- 蓝牙入口按已注册播放器服务能力显示；没有对应能力的板不显示蓝牙入口。
- CPU 浅/深休眠、软件关机和重启的接口与调用顺序已定义。当前尚未接入安全收尾后端，因此这些能力不会被公开到设置。
- P4/lckfb 未确认电池检测硬件，不显示虚构的电量。

`python -m unittest test_power`（在 tests 目录运行）编译真实公共实现，覆盖派生、封存、无后端、错误电池数据、非法模式/唤醒组合、准备失败、休眠失败后的恢复、重入拒绝、超时抑制、唤醒吞手势和屏幕操作失败。

### 滚动设置中的滑条手势

亮度、音量保留扩大的触摸区域。在 LVGL 滑条类处理之前先判断手势方向：尚未超过手势阈值时不修改数值；纵向手势交给设置页滚动，整次手势都不修改或保存亮度/音量；横向手势继续调节，短点轨道仍可选择数值。
`tests/test_slider_axis.py` 验证方向锁定、快速滑动、点击与输入设备兼容；模拟器 `desktop/test_mixer_gestures.py` 经真实 LVGL 触摸链路验证两根滑条上的纵向滚动不改配置、横向拖动仍能调节。


熄屏设置与立即熄屏使用加高的独立按钮，紧凑屏幕上也保留至少 56 物理像素高度、18 物理像素间隔。按钮保持整次触摸归属，超过拖动阈值或丢失按压时取消点击；即使位于滚动边界，也不把滚动释放当作立即熄屏。


公共设置页会逐个消费触摸采样，保留真实按下位置，避免多个采样在一次 LVGL 读取前覆盖。横向意图需要明显的水平位移和连续不同坐标的确认；静止坐标的重复读取不算确认，移动后仍不明确的释放按取消处理。这些规则在共享 Launcher 源码中实现，ESP-IDF、Zephyr 和桌面均使用同一份逻辑，无按芯片分支或单板阈值。


### 公共滑条修复实机验收

2026-11-17，鱼鹰光电 P4C5 与 FAKE POD NANO PRO 烧录相同公共实现后，用户确认验证通过：设置页从滑条开始上下滚动、先轻微左右晃动再上下滑动不再误调数值，FAKE POD NANO PRO 的正常横向调节保持顺畅。
此记录只覆盖本轮设置交互修复，不表示 CPU 休眠、软件关机或重启后端已完成。
